Regeln beim Parallelisieren

  • Migrationsnummern: Zwei parallele PRs mit neuer Migration nehmen dieselbe Nummer. Der später gemergte PR benennt seine Migration vor dem Merge um.
  • Sammeldateien (app/src/routes.php, Permission, AuditAction, Navigation, Specs) erzeugen kleine Merge-Konflikte – vor dem PR mit main abgleichen.
  • PHPUnit lokal nie gleichzeitig laufen lassen (gemeinsame DB vereinsbelege_test), oder je Lauf TEST_DB_NAME setzen. Sonst die CI im PR prüfen lassen.
  • Docker sieht nur C:\dev\vereinbelege. Sitzungen in Worktrees oder in der Cloud verlassen sich auf die CI; die Browser-Prüfung danach lokal nachholen.
  • Vor jedem Merge: /code-review high, vor allem nach Auto-Sitzungen.
  • Diese Seite pflegen: Ändern sich Reihenfolge, Abhängigkeiten oder Einstufung, die Zeile in PLAN im selben PR anpassen. Den Status musst du nicht pflegen – er kommt live von GitHub.
